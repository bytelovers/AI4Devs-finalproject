## User Story

**Como** Carlos el Organizador,
**quiero** poder alternar entre tema claro, oscuro y del sistema, y ver toda la app rediseñada con una paleta Sage & Amber sin neones molestos,
**para** mejorar la accesibilidad y ergonomía visual de la app.

## Acceptance Criteria

### Scenario 1: Manual theme persistence — Light mode
```gherkin
Given the user is on any screen with the side drawer open
When the user selects "Light" from the ThemeSelector
Then the app immediately switches to light mode (#FFFFFF base background)
And the selection is persisted in localStorage under the key "theme"
And the <html> element receives the class "light"
And refreshing the page loads in light mode without flicker (no FOUC)
```

### Scenario 2: Manual theme persistence — Dark mode
```gherkin
Given the user has previously selected "Light" mode
When the user opens the drawer and selects "Dark"
Then the app immediately switches to dark mode (#111415 base background)
And localStorage "theme" is updated to "dark"
And the <html> element receives the class "dark"
And refreshing the page loads in dark mode without flicker
```

### Scenario 3: System fallback
```gherkin
Given the user selects "System" from the ThemeSelector
When the OS is in dark mode (prefers-color-scheme: dark)
Then the app renders in dark mode
When the OS switches to light mode
Then the app re-renders in light mode reactively
And localStorage "theme" is set to "system"
```

### Scenario 4: Zero neon/glow styling across all screens
```gherkin
Given the app is running in either light or dark mode
When inspecting OCRScanner, Allocation, BillingHUD, and PayerWheel views
Then no element has a box-shadow or text-shadow referencing neon colors
And no CSS animation applies opacity-flickering or color-pulsing effects
And viewfinder borders in OCRScanner use solid Sage Green (#5F8575) only
```

### Scenario 5: Inverted QR modal in dark mode
```gherkin
Given the app is in dark mode
When the user opens the QR payment modal in BillingHUD
Then the QR image container applies CSS filter: invert(1) hue-rotate(180deg)
And the result displays as white QR blocks on a dark background
And no neon glow is present around the modal container
```

### Scenario 6: Winner physical bounce animation (1.2x scale)
```gherkin
Given the Payer Wheel has finished spinning
When the winner avatar is displayed
Then the avatar scales from 1.0x to 1.2x over 300ms
And the animation uses a cubic-bezier(0.175, 0.885, 0.32, 1.275) easing (physical bounce)
And no glow or neon outline is applied to the avatar during or after animation
```
